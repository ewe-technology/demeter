# H68：看多的 BTC 比例和看空的買單比例分開設定

日期：2026-10-21（登記，還沒有跑任何一步）
前一份：[plan_2026-10-21_c1_inventory.md](plan_2026-10-21_c1_inventory.md)（H67）；總整理見 [c1_drawdown_2026-10-21_report.md](c1_drawdown_2026-10-21_report.md)

## 0. 為什麼要做

到目前為止的配置，不是只縮看空的買單（固定小額買單、`dd30`），就是兩邊一起縮（整本帳縮小部位，第 7 節）。還沒有測過「看多時少持一些 BTC，看空時保留比較大的買單」。理由是：H58 最深那段，看多價格虧了 25.3 pt，看空價格扣掉手續費約虧 9.3 pt；之前的修法大多只削看空的買單，同時削掉了手續費收入。

**事後的線性估算（2026-10-21，只列出）**：用存好的小時帳，看多的每小時報酬乘上 w_on、看空的乘上 s_off（換邊那根 K 線按 w_on 縮放；同樣算法用在現行自己的帳上，會算回現行本身）：

| w_on / s_off | `99ac` 報酬 / 回撤差 | `9db9` 報酬 / 回撤差 |
|---|---|---|
| 0.8 / 0.4 | +168.6% / +4.5 pt | +145.0% / +1.5 pt |
| 0.8 / 0.6 | +193.8% / +2.3 pt | +153.7% / −1.1 pt |
| 0.9 / 0.4 | +190.5% / +1.5 pt | **+164.8% / −1.5 pt** |
| 0.9 / 0.6 | **+217.7% / −0.6 pt** | +174.2% / −4.0 pt |

（`dd30`：`99ac` +206.1%、`9db9` +173.0%。）

`99ac` 符合新目標的格子排成一條對角線，`9db9` 沒有任何一格符合，但差距（最好的 (0.9, 0.4) 比 `dd30` 少 8.2 pt）落在線性估算的誤差附近：價格衝擊跟交易金額的平方成正比，看多部位縮小之後，換邊的衝擊比線性估算的少。所以用 Demeter 的精確成本，跑最接近的 4 格，讓這個問題有一個確定的答案。這 4 格是看過線性估算之後才選的，全部是樣本內。

## 1. 目標與共用設定

照 [plan_2026-10-21_c1_spells.md](plan_2026-10-21_c1_spells.md) 第 0 節的新目標（2026-10-21 跟使用者確認）。其他照 H48 的 C1：BTC EMA100 濾網、買單 [p/1.40, p×1.01]、1 份、00 時判定、每天 00:00 檢查出界、$100k、小時資料、H48 成本；`99ac`、`9db9`；16 個窗口加一條 2022-01-01～2026-09-30 的連續帳。

## 2. 版本

| 版本 | 看多時 | 看空時 |
|---|---|---|
| `w80_s40` | 帳的 80% 持有 WBTC，其他持有穩定幣 | 每次放買單（翻空那次和每次移倉）用帳的 40%，其他持有穩定幣 |
| `w80_s60` | 80% WBTC | 買單 60% |
| `w90_s40` | 90% WBTC | 買單 40% |
| `w90_s60` | 90% WBTC | 買單 60% |

- 看多時的比例只在翻多那次調整（跟現行一樣，期間不再平衡）；看空時的買單照 H67 的固定小額買單做法，每次放單都用整本帳 × s_off，可以從穩定幣補回去。
- **相鄰關係**：w_on 相同、s_off 不同的兩格互為相鄰；s_off 相同、w_on 不同的兩格也互為相鄰。

## 3. 判定（事先寫死）

一個版本**通過**，要同時符合：

1. 兩個池子的連續帳最大回撤，各自不比同一池的現行深超過 2 pt；
2. 兩個池子的連續帳淨報酬，各自高於同一池的 H59 `dd30`。

通過的版本裡，選 `99ac` 淨報酬最高的。都沒有通過，就保留 `dd30` 當研究基準，**「兩種狀態怎麼分配風險」這個問題在這次的範圍內結案**，不加新的格子。

**只列出**：Calmar、窗口的「版本 − 現行」中位數和 > 0 的個數、各年報酬和回撤、價格衝擊和 gas（跟線性估算比，精確成本差了多少）、C1 原版最深那段（2025-08-14 → 2026-06-05）和 2026-01-01 → 09-30 的報酬和回撤、相鄰格子是否也符合。

## 4. 執行

- **程式**：`gate_lp_options.py` 加 `--h68-check`、`--h68`。看多比例用現有的 `spot_weight`，看空買單用 H67 的 `ladder_size`。
- **一致性檢查**（跑之前，不符合就不開始）：w_on = 1.0、s_off = 1.0 在 `99ac` 2022-01 窗口，跟 H48 的 C1 買單逐位相同。
- **機器**：`aws-strategy-ssm`，2 個 worker。
- **規模**：4 個版本 × 2 個池子 × 17 條 = 136 條，大約 20 分鐘。

### 只列出

- **精確成本比線性估算好很多**：`w90_s40` 在 `9db9` 線性估算是 +164.8% / −1.5 pt，Demeter 是 +173.5% / +0.0 pt；`w90_s60` 在 `99ac` 線性估算是 +217.7% / −0.6 pt，Demeter 是 +230.0% / +1.1 pt。原因跟登記時寫的一樣：部位變小之後，換邊的價格衝擊比線性估算的少（`w80_s40` 在 `99ac` 的價格衝擊佔本金 15.8%，C1 原版 48.2%，現行 21.8%）。
- **Calmar**：4 格在兩個池子都高於 `dd30`（`99ac` 0.733～0.777 對 0.694；`9db9` 0.588～0.627 對 0.571），`99ac` 也都高於 C1 原版（0.736）的有 `w80_s40`、`w80_s60`、`w90_s60`。
- **跟現行比**：`w80_s40`、`w80_s60`、`w90_s40` 在兩個池子都是報酬比現行高、回撤也比現行淺。但在 `9db9`，窗口「版本 − 現行」的中位數只有 −1.0% / −0.9% / +1.0%，> 0 的只有 7 / 7 / 9 個窗口（16 個裡）。所以好處主要來自連續帳的回撤路徑，不是每個窗口都贏現行。
- 各年報酬（`99ac`，2022 / 2023 / 2024 / 2025 / 2026）：`w80_s60` +5.3 / +65.1 / +69.9 / +3.1 / +1.9%；`w90_s40` +1.4 / +69.5 / +70.2 / +0.2 / +3.1%；`dd30` +2.8 / +78.3 / +68.1 / −2.0 / +1.4%；現行 −5.6 / +69.8 / +64.3 / −4.9 / +4.5%。2026 年 4 格都輸給現行（+1.8%～+3.2% 對 +4.5%）。

### 讀法

- **分開設定兩邊的比例，得到的是另一個取捨點**：回撤比 `dd30` 淺（`99ac` 淺 0.2～5.8 pt），報酬相近或稍低，Calmar 比較高。在登記的目標（兩個池子的報酬都要高於 `dd30`）下，沒有一格符合。
- 這 4 格的差距都在幾個 pt 以內，而且格子是看過線性估算才選的。所以這個結果不能讀成「分開設定有效」，也不能讀成「分開設定無效」；比較準確的說法是：**在這個範圍內，它跟 `dd30` 差不多，沒有明顯更好。**
- 如果之後要改用「Calmar」或「回撤比現行淺」當目標，這 4 格會是候選；但那是新的目標，要重新登記，不能從這張表直接挑。
