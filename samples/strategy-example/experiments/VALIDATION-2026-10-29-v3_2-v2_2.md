Gas condition (spec section 6): a daily claim also needs the estimated gas <= $0.2, else it waits. Estimate = (75k gas
per live band + 120k for the ETH -> USDC swap) x the last hourly mainnet gas price at or before the 00:00 judgement x the
pool's ETH price (`claim_gas_usd`, `gwei_at`; units are assumptions, `LOOKAHEAD-AUDIT-2026-10-29.md` section 3). The
swap is always counted, so even one band costs 195k gas (the audit's "one collect" column has no swap). Gas samples that
are empty, zero or ~1e-7 gwei (38 of 45k) are data errors and dropped (`valid_gas`). Claims at a rebuild are not gated.

Metrics: `strategy_layers.py l0` on the UTC-0 daily net value (00:00 of each day plus the run's last value); CAGR on
calendar days; Calmar = CAGR / |max DD|. v2.2's daily file ends at the 2026-08-31 00:00 execution, so its end value is
one day short of `eth_summary.csv` (`eth_ratio_end` 6.255 / 5.738 ETH at 23:59, reinvest on / off).

## L1 walk-forward + L5 out-of-sample: the yearly table

### Rule (pre-registered 2026-10-30, before any yearly number was computed)

Nothing in v3.2 / v2.2 is refitted, so L1 reduces to one yearly table with the constants held fixed, and L5 to
pseudo-OOS on the later years (all pool data predates the 2026-10-27 spec freeze; `VALIDATION-LAYERS-FIT.md`). No new
backtests: the table cuts the six L0 runs above (same engine, costs, windows; data ends 2026-08-31).

Windows, on the UTC-0 daily net value of `strategy_layers.py` (`daily_net_value`):
- calendar years: each year a run covers, from its first daily value in the year (00:00 on 1 January, or the run
  start) to the first daily value of the next year (00:00 on 1 January, or the run's last value). A year the run does
  not cover in full is marked partial (v3.2 2021 from 05-06, v2.2 `0x4585` 2021 from 11-02, `0x7aea` 2024 from 09-14,
  every 2026 row to 08-31).
- anchored windows: from 2022-01-01 to the end of 2022, 2023, 2024, 2025 and to the run's end (`0x7aea`: from its
  start, to the end of 2024, 2025 and the run's end).
- per window: return (end / start − 1), CAGR (calendar days), max drawdown inside the window, Calmar = CAGR / |max DD|.
  Return > 0 means beating the run's unit held still (USDC for v3.2, ETH for v2.2).

Pass rules, judged per run (both reinvest modes must pass for the strategy to pass):
- **L1 (yearly stability)**: return > 0 in at least 3 of the 4 full years 2022-2025. The partial years are reported,
  not judged.
- **L5 (pseudo-OOS)**: the later window 2024-01-01..run end has CAGR > 0 and Calmar >= 0.5 x the Calmar of the earlier
  window 2022-01-01..2023-12-31 (if the earlier Calmar is <= 0, CAGR > 0 alone).
- Judged runs: v3.2 on `0x88e6`, v2.2 on `0x4585`. v2.2 on `0x7aea` (2 years, one full year) is reported, not judged.
- Clean OOS (data after the 2026-10-27 freeze): none yet. Rows are added monthly from the first full month (2026-11),
  by refetching the pools and rerunning the frozen code; they do not change the verdict above until Dino says so.

These thresholds are my reading of "judged on the later years" (`VALIDATION-LAYERS-FIT.md` L5); Dino may change them.

### Deviations (L1 + L5)

- Window: `VALIDATION-LAYERS-FIT.md` plans 2026-01..09. The pool data reaches 2026-09-30, but the L0 runs stop at
  2026-08-31 (spec section 7 window), and the table keeps the L0 window.
- QUAN-1216 asks for scorecards on v2.2 `0x7aea` too. The pre-registered rule reports it but does not judge it (one
  full year), so it has no L1 / L5 pass or fail.
- The 2021 partial years are printed although the plan lists 2022 onward. They are marked partial and not judged.
- Edge case found in review, after the results: an earlier window with no drawdown has infinite Calmar, which the rule
  does not cover. The code now returns "not judged" for it. It does not apply to any of the six runs.

### Not done in L1 + L5

- Clean OOS rows (after the 2026-10-27 freeze): none yet. The first full month is 2026-11. Refetch `0x88e6`, `0x6c56`,
  `0xd0b5` and `0x7aea` in early December and rerun the frozen code.
- No benchmark per year (hold ETH for v3.2, hold BTC for v2.2): return > 0 only beats the unit held still.
