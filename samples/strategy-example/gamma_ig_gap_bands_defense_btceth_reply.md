# ETH-BTC 回測比對確認事項回覆

感謝詳細比對。兩次判定相反都來自價格來源的正常差異，不是資料異常；真正需要統一的是 EMA 起始日（第 3 點）與 F 的定義（第 5 點）。各點回覆如下。

## 1. √(ETH×BTC) 的價格來源

本方 G、R 都使用 Uniswap 主網池價：

- ETH/USD：WETH/USDC 0.05% 池
- BTC/ETH：WBTC/WETH 0.05% 池
- G = ETH/USD × √(BTC/ETH)。BTC/USD 由兩個池價推導，沒有另外使用 BTC/USD 報價。
- 時間點：UTC 每日最後一根 1 分鐘 K（23:59）的收盤價；該分鐘沒有成交時，沿用上一筆價格。

我們用分鐘資料檢查了貴方指出的幾個日期，兩個池子在收盤前幾乎每分鐘都有成交，沒有發現異常跳價：

| 日期 | 本方收盤 vs 最後一小時中位數 | 說明 |
| --- | --- | --- |
| 2024/7/25（EMA110 撤出） | +0.08% | 平穩收盤。差異來自價格來源本身（WBTC 對 BTC、USDC 對 USDT、池價對交易所價），剛好落在 EMA110 的臨界點上。 |
| 2025/11/20（約 0.3% 的例子） | −0.90% | 收盤是最後一小時急跌中的最低點，屬於真實行情波動。行情急變時，池價 23:59 與 Binance 00:00 收盤自然會拉開，不是資料錯誤。 |
| 2025/11/22（低點 L） | −0.21% | WBTC/WETH 池最後一筆成交在 23:55，價格落後約 4 分鐘，L 因此比貴方低約 0.13%。 |
| 2025/11/25（第 1 階段門檻） | −0.15% | 本方收盤高出門檻 0.06%，貴方低於門檻 0.05%，同樣是臨界點上的來源差異。 |

結論：兩次判定相反都是正常的價格來源差異，剛好發生在臨界點，不是資料異常。不過值得注意的是，訊號只差 0.0X% 就讓年末原資相差約 0.19 ETH，可見策略對臨界日的價格相當敏感，不論使用哪個價格來源都一樣。

## 2. 規格上的統一

本方的 R = 1 ÷ WBTC/WETH 池價，相當於直接使用 ETHBTC 交易對，不是用 ETHUSDT / BTCUSDT 相除。

如果貴方希望統一改為「訊號用 Binance 日K收盤，池價只用於 LP 價值與手續費計算」，本方可以修改並重新測試，但需要一些時間。這樣也能一併解決第 1、3 點的差異。

## 3. EMA 的起始日

目前從 2021-05-13 開始，是因為 Uniswap v3 WBTC/WETH 池的資料只到這一天，用鏈上資料無法回溯到 2017-08-17。另外需要說明兩點：

- 2022〜25 年通算的暖機期只有約 230 天。EMA120 的初始值還有約 2% 的權重，並沒有完全收斂。
- 虛擬帳戶第一天若收盤高於 EMA，會直接視為全額部署，沒有經過階段回補。

若改用 Binance 日K（從 2017-08-17 開始），G 的四條 EMA、R 的 EMA100 以及四個虛擬帳戶的狀態機都可以從 2017-08-17 連續計算，上述兩個問題也會一併消失。

補充：各單年度的回測（2023、2024、2025）各自的暖機起點不同，所以和通算中同一年的結果不會完全一致。改為 2017 年起算後，這個差異也會消失。

## 4. 日期標記

確認如下：

- daily 檔的日期是「執行日（D+1 00:00）」，所以 F 會和貴方前一天的 F 一致。
- signal_frame 檔的日期是「判定日（D 日收盤）」，和貴方相同。

例如：signal_frame 的 2024/7/25 F = 0.25，在 daily 檔中出現在 2024/7/26。

## 5. F 的定義

本方目前使用階段值：每個虛擬帳戶取 0 / 0.25 / 0.5 / 0.75 / 1，四個帳戶平均後即為 F。這次雖然沒有造成交易差異，但我們同意規格需要統一。

若採用貴方的「各虛擬帳戶的 LP 價值比例」，還需要確認虛擬帳戶本身 LP 的區間形狀（寬度、中心、重建規則），以便計算其價值變動。麻煩將這部分補進規格。

## 6. 手續費與池子

- 使用的池子：以太坊主網 WBTC/WETH 0.05%（0x4585FE77225b41b697C938B018E2Ac67Ac5a20c0），這也是規格書校正手續費所用的池子。
- 手續費依鏈上每分鐘的實際流動性占比計算，依規格不再投入。期間 LP 平均占資金約 68%，共重建 172 次（其中出界重建 11 次）。
- Base cbBTC/WETH：本方正在下載這個池子的資料，完成後會提供回測結果。

另外提醒：主網 WBTC/WETH 和 Base cbBTC/WETH 的成交量與 TVL 結構不同，用主網資料校準的手續費模型不一定適用於 Base。建議等 Base 的回測結果出來後再校準一次。
